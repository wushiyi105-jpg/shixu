# 时序 shixu

[![test](https://github.com/wushiyi105-jpg/shixu/workflows/test/badge.svg)](https://github.com/wushiyi105-jpg/shixu/actions) [![Python 3.10+](https://img.shields.io/badge/Python-3.10%2B-3776AB?logo=python&logoColor=white)]() [![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](./LICENSE)

一份 CSV 时间序列丢进去，它把异常点找出来，然后让模型说人话解释。

算法负责「哪里不对」，模型负责「可能是为什么、先查什么」，程序再回头核验模型嘴里的每个数字——对不上数据的，直接标出来。

![演示](assets/demo.gif)

## 它到底在做什么

三件事，顺序不能反：

1. **找点**。滚动中位数 + MAD 抓单点尖峰，前后窗对比抓台阶，间隔检测抓断档，空值单独报。
2. **解释**。把异常清单、统计摘要、你写的业务背景一起给模型，要求它给出原因、排查动作、把握程度。
3. **核验**。模型解释里出现的数字，必须能在异常值、基线、统计摘要里找到。找不到就是编的，标红。

第 3 步是我最想强调的地方。模型解释异常时特别爱补数字：「大概影响了 30% 的用户」「估计少了 5000 单」。这些数字它算不出来，只是为了让句子看起来完整。所以我不让它算，只让它引用。

## 三个算法

| 检测 | 做法 | 默认阈值 |
| --- | --- | --- |
| 尖峰 / 骤降 | 该点之前的滚动中位数与 MAD，稳健 Z 分数 | 窗口 14，Z 3.5 |
| 台阶 | 前窗中位数 vs 后窗中位数，且之后一窗要稳住 | 窗口 7，2.0 倍 MAD |
| 断档 | 相邻间隔超过典型间隔的倍数 | 2 倍 |
| 缺失 | 该行数值为空 | — |

稳健 Z 用中位数和 MAD 而不是均值和标准差，是因为异常点自己会把均值和标准差拽偏：三个大促日能把一个月的标准差翻倍，然后什么都抓不到了。

还有一条不起眼但很要紧的规矩：**起步阶段不判尖峰**。前 7 个点没有像样的历史基线，MAD 小得离谱，任何一点起伏都会被算成「偏离 20 个 MAD」。

## 真实的一次返工：台阶报了 16 个，全是噪音

第一版跑样例数据，日活那一列出这些：

```
异常：尖峰 2、骤降 6、台阶 16、断档 1、缺失 1
```

我埋的异常只有 5 个，它报了 26 个。台阶尤其离谱——16 个，日期从 9 月 15 号一路铺到 10 月 20 号，几乎每天都在「换台阶」。

三个病灶：

**一、均值太脆。** 前后窗用均值比。10 月 3 号那天埋了个 900 的骤降，它落进哪个窗口，那个窗口的均值就被拽下去 100 多，于是相邻好几个位置同时「检出台阶」。换成中位数，一个 900 落在 7 个点里，中位数纹丝不动。

**二、同一个台阶会被报七八次。** 滑窗逐点判，一个真实台阶会让前后七八个位置都超阈值。加非极大值抑制：按得分排序，一个窗内的其余候选全丢掉。

**三、起点还会偏。** 去重之后留下的那个位置，往往不是台阶第一天——得分打平时它落在台阶前一两天（那时窗口里的中位数已经翻过去了，分一样高）。所以先往后推到「真正站上新水平」的那天，再往前回溯到第一个已经在新水平上的点。

改完，同一个数据集：

```
异常：尖峰 1、骤降 1、断档 1、台阶 1、缺失 1
4. [台阶] 2026-10-16，值 2597（基线 3368）
```

起点正对 10 月 16 号，也就是我埋台阶的那天。26 个变成 5 个，5 个和我埋的 5 个一一对上。

还顺手加了一条：台阶一旦被认出，台阶后那一窗里的「骤降」多半只是它自己的回响——中位数还停在旧水平，新值当然看着像掉下去了。落在新台阶 ±15% 的一律压掉。

## 数字核验也踩了坑：31 个假警告

第一版核验的允许集合只放了异常值、基线、统计摘要，然后跑样例，结果每条解释下面都挂一串红：

```
可能原因：9 月 21 日出现历史最高值 6200，最可能是大促……
! 这句里的数字对不上数据：9, 21, 9, 9, 21
```

**日期不是数据。** 模型复述「9 月 21 日」是它该做的事，我却把 9 和 21 当成它编造的数值。一个机制如果对每条正常输出都报警，那它等于没有。

修法：核验前先把日期形态剔掉——`2026-09-21`、`9月21日`、`9/21`、`9-21`、`10月`、`9 点 30 分` 全都不算数据；小整数（≤5）当序号放过；`note` 里程序自己写的数（「隔了 4 个周期」「正常约 24 小时」）加进允许集合。

改完同一批解释：**0 条假警告**。而故意写一句「大概涨了 30%」，仍然会被抓出来——30 不在允许集合里，也不是日期。

单测里这几条都是硬的：`test_date_is_not_data` 逐个断言五种日期写法不报警，`test_fabricated_percent_caught` 断言「30%」必须被抓。

## 快速开始

```bash
git clone https://github.com/wushiyi105-jpg/shixu.git && cd shixu
cp .env.example .env      # 填 LLM_API_KEY

python -m shixu add samples/daily-active.csv --note "自营商城，9 月中做过一次大促，月底上了新版首页"
python -m shixu detect 1 --out reports/日活异常报告.md
```

不带模型、只跑算法：

```bash
python -m shixu detect 1 --no-model
```

起网页：

```bash
python -m shixu serve        # http://127.0.0.1:8770
```

## 命令

| 命令 | 做什么 |
| --- | --- |
| `add <csv...> --name --note` | 导入 CSV，按内容哈希去重。第一列时间，其余能转数字的列都是指标 |
| `list` | 数据集列表和检测次数 |
| `detect <id> [--column] [--window] [--z] [--shift-ratio] [--no-model] [--json] [--out]` | 跑检测并写库，可选导出 markdown |
| `show <id>` | 看数据集概况和每列上次检测时间 |
| `svg <id> --column --out` | 导出一张 SVG 曲线图，异常点带圈 |
| `rm <id>` / `stats` / `serve` | 删数据集 / 统计 / 起网页 |

`--note` 里的业务背景会进模型提示词。写清楚「月底上了新版首页」这种上下文，模型给的原因会具体得多——这是它唯一能拿到的、算法看不见的信息。

## 网页

左边数据集和指标，右边曲线 + 异常清单。图是内联 SVG，没有图表库：960×300 的一段字符串，折线在缺失处断开，异常点画圈（红尖峰、黄骤降、蓝台阶、灰虚线断档）。

「只跑算法」那个按钮不调模型，用来快速看阈值合不合适。

## 设计取舍

- **零第三方依赖**。CSV、统计、SVG、HTTP 全是标准库。装环境这一步越轻，别人越可能真的跑一遍。
- **异常点结构统一**。`{kind, index, time, value, baseline, deviation, note}`，五种类型一套字段，前端和模型提示词都不用分支。
- **模型失败不丢数据**。解释挂了，异常点照常入库，报告里写明「模型解释没跑成：接口 429」。
- **每次检测覆盖同一列**，不堆历史版本。阈值改了重跑是常事，留一堆旧结果反而不知道该看哪份。
- **平均值不进报告**。统计摘要里有 mean，但解释永远拿中位数说事——含义更稳。

## 测试

```bash
python -m unittest discover -s tests
```

127 个用例，全离线：模型调用被替身接管，HTTP 用 `port=0` 起真服务再打。覆盖读 CSV 的九种时间格式、五种缺失标记、台阶的三种伪阳性（单点污染、来回弹、缓坡）、日期核验、SQLite 去重与覆盖、SVG 缺值断线。

跑测试时还揪出一个真 bug：CLI 各子命令不关 sqlite 连接，Windows 上连临时库都删不掉，报 `PermissionError: 文件被占用`。修在 `main()` 的 `finally` 里统一关——顺带把 Python 3.13 那串 `ResourceWarning` 也治了。

## 配置

`.env`（已在 `.gitignore` 里）：

```
LLM_API_KEY=...
LLM_BASE_URL=https://open.bigmodel.cn/api/paas/v4
LLM_MODEL=glm-4.6
```

兼容任何 OpenAI 风格 `/chat/completions` 接口，DeepSeek、Ollama 都能接。命令行 `--api-key --base-url --model` 可临时覆盖。
